## 2. Persistence inventory

### Authoritative domain/application persistence

Drift/SQLite:
- lib/data/local/database/app_database.dart
- lib/data/local/database/qaza_records_dao.dart
- lib/data/local/database/tables/qaza_records.dart
- account/profile/revision state in the same AppDatabase

Authoritative tables:
- qaza_records
- qaza_additions
- qaza_deletion_actions
- qaza_deletion_action_record_snapshots
- qaza_profile_plan_provenance
- local_accounts
- account_profiles
- account_plan_revisions
- app_session_state
- device_metadata
- meta_store

### Presentation persistence

SharedPreferences is intentionally restricted to:
- language_code
- qaza_theme_mode

Runtime access is centralized in lib/app/providers.dart and is enforced by tools/offline_architecture_check.py.

### Database encryption key

flutter_secure_storage is used by the local database encryption-key store. This is device-local security state, not cloud synchronization.

### User-controlled backup files

Portable JSON backups are generated by:
- lib/data/data_transfer/local_backup_service.dart
- lib/features/data_management/qaza_data_management_screen.dart

Backups are local files shared through the operating system. They are not cloud storage.

## 4. Authentication and cloud inventory

Production Phase 1 contains:
- no Firebase runtime initialization
- no Firebase Authentication
- no Firestore
- no Firebase App Check
- no Google Sign-In
- no Google Drive API
- no cloud adapter runtime path
- no WorkManager
- no connectivity_plus

The account/session layer is local:
- lib/features/account/account_session_manager.dart
- lib/data/local/account_local_store.dart

The architecture policy and new phase-boundary policy both fail the build if cloud/authentication dependencies or Phase-2 imports are reintroduced.

## 5. Background worker inventory

No production WorkManager/background cloud backup worker remains in Phase 1.

The application performs local persistence synchronously/transactionally through Drift.

## 7. Startup/onboarding state inventory

Startup is composed from:
- local account/session initialization
- Drift meta_store.is_onboarding_completed
- account-scoped profile loaded from Drift

Primary sources:
- lib/features/account/account_session_manager.dart
- lib/data/local/account_local_store.dart
- lib/app/providers.dart
- lib/features/onboarding/startup_gate.dart
- lib/main.dart

Routing rule:
- onboarding flag false → onboarding
- onboarding flag true → Home, subject to profile completeness validation

No remote startup check is allowed.

## 10. Closure rule

Phase 0 is considered evidence-complete when this inventory, baseline record, and architecture policies are committed.

Phase 1 remains closed only after:
- the full offline functional matrix completes on an Android emulator with airplane mode enabled;
- all automated regression tests pass;
- explicit Phase-1→Phase-2 dependency enforcement passes;
- APK/AAB and manifest gates pass;
- PR #263 is green and merged.

Physical device certification for real GPS acquisition and native location-service resolution remains a release-certification activity rather than a substitute for automated offline proof.
